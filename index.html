04 projects

Tooling I've built

MCP-Sentinel

validated
n8n · MCP protocol · Claude reasoning agent

Turns the tables on AI infrastructure itself — an agent that pentests other AI agents and MCP servers instead of web apps. Most AI security tooling checks whether a model behaves safely; this checks whether the surrounding infrastructure — the tools it's wired to, the permissions it's granted — actually holds up under adversarial pressure. It started as a way to stress-test my own AI agent before I trusted it with anything else, then grew into a general-purpose auditor.

  • Discovery pipeline enumerates a target's full tool manifest via the MCP initialize handshake and tools/list call, gated behind a scope guardrail so it never touches anything outside the agreed target
  • Auth/JWT tampering, scope audits with real proof-of-exploit, and secrets scanning run as dedicated check branches
  • Tool-poisoning and schema-drift checks catch manifests that lie about what a tool does or change definitions mid-session
  • A live prompt-injection test wires a real AI agent to the target's actual tools and watches whether it acts on a hidden instruction buried in untrusted content
  • Validated first against a self-built test target, then against a live external MCP server with a planted vulnerability — correctly flagged it as a confirmed exploit
  • Built end-to-end in n8n, with a Claude-powered reasoning agent that triages raw check output into a disclosure-style report a human reviewer could act on directly

Spectre

phase 2
Python · Flask · Kali Linux

An automated reconnaissance and vulnerability intelligence engine for mapping an application's real attack surface. Built to replace the manual grind of stitching together recon tools by hand — one pipeline takes a target from nothing to a structured, ranked picture of what's actually exposed. It's already surfaced real findings, not just test-lab ones: a live scan against xealenergy.com uncovered an exposed Okta OAuth configuration pulled straight out of a React bundle, which turned into a responsible disclosure report.

  • Multi-stage pipeline: subdomain enumeration, endpoint discovery, attack-surface mapping
  • Runs in four phases — discovery, crawling, analysis, active recon — with controlled concurrency instead of firing every module at once
  • Integrates Katana, GAU, and HTTPX with custom parsers behind a scan-ID isolation model, so concurrent scans never step on each other's results
  • Detection modules for exposed API endpoints, sensitive files, and misconfigured assets
  • Combines live crawling, JavaScript analysis, and historical-source data for coverage a single tool would miss on its own
  • Currently in phase 2 (the vulnerability scanner); next up is a module for probing stale 403 responses on staging and demo subdomains
